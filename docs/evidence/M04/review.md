# M04 independent security and correctness review

Date: 2026-10-12. Scope: administrator integration configuration, HTTP/DNS source transport, magnet/metainfo parsing, upload staging and retention, discovery permission stamps, snapshots, result normalization and private source resolution. Read-only implementation review; this reviewer changed only this evidence file. The parent and assigned workers own implementation and tests. No external accounts, production data or external network services were contacted by this reviewer. Independent experiments used generated metainfo, fake DNS and the in-memory local test host.

## Findings and final source assessment

No remaining concrete P1/P2 defect was identified in the final reviewed M04 implementation. The final health-response shape correction is also resolved in source. Corrections inspected in source are recorded below. This is a code-boundary assessment; final integrated acceptance remains the parent's responsibility.

| Finding | Severity | Correction confirmed |
|---|---|---|
| Multipart binding and payload copies happened before upload admission, allowing concurrent expensive parsing despite the persisted-row quota. | P1 | `Program.cs` admits at most two uploads before binding, limits the whole request and multipart fields/headers, and normalizes the upload path before admission. Upload hashing now uses payload SHA256 directly. |
| Expired upload files/rows were never removed, and write/cancellation failures before database save could leave untracked files. Four uploads every 30 minutes bypassed the storage quota indefinitely. | P1 | `SourceHousekeeping.PruneUploadsAsync` removes expired identity-matching files/rows and bounded orphan files under `WriteGate`. Admission counts all retained rows and filesystem entries, caps four/user and 32/global, and checks free space. The cleanup guard now covers create/write/flush/persist failures. Replaced files fail closed rather than being deleted blindly. |
| Magnet/upload resolution returned after tracker DNS without a final live permission check; an upload could expire during the wait. | P1 | Every successful source branch checks the current user/session and the original permission stamp. Upload resolution additionally rechecks ownership and expiry after asynchronous DNS. See `Sources/SourceService.cs:19` and `:31`. |
| Ancestor collisions could evade adjacent raw-path sorting, including `a`, `a-/middle`, `a/child`, case and normalization variants. Full-path length counted characters instead of UTF8 bytes. | P2 | `Metainfo.Parse` builds normalized case-folded path identities and checks every ancestor against the set. Component and full-path limits use UTF8 bytes. See `Sources/Metainfo.cs:72` and `:103`. |
| V2 Merkle verification repeated a shared piece layer for every file. A small torrent could cause hundreds of MB of allocations; the maximum accepted input could multiply this work thousands of times. | P1 | Successful layer verification is memoized per pieces-root/layer length within one parse; each file still independently checks its required layer length. See `Sources/Metainfo.cs:85` and `:93`. |
| Single-file V2/hybrid paths and the V1 piece-size profile were overly restrictive; hybrid alignment and mixed single/multifile layout validation were incomplete. | P2 | V2 tree traversal preserves the actual relative layout, single-file paths avoid a duplicate name, V1 supports the bounded 64MiB profile, and hybrid file/padding alignment and mixed-layout checks are explicit. Original bencoded `info` bytes remain the hash input; layers are verified without rewriting metainfo. |
| Duplicate releases could mix counts from different providers: seeders 5 plus unknown leechers, merged with another provider's 10/2, yielded 5/2/12. | P2 | Aggregation preserves one coherent report and merges only source options/categories; duplicate swarm counts are not combined. See `Queries/DiscoveryQueryWorker.cs`, `AggregateRelease.Merge`. |
| Finished snapshots were unlimited until TTL cleanup, and new idempotency keys against a cached query created unlimited operation rows without upstream work. | P1 | Creation checks retained snapshot limits (64/user, 256/global) and discovery operation limits (256/user, 4096/global) under `WriteGate`. Existing-key replay and cached reads remain available; cleanup removes old catalog/jobs/operations. See `Queries/DiscoveryQueries.cs:94` and `:117`. |
| Health testing called `TryGetProperty` on valid array/string/null upstream JSON, which throws `InvalidOperationException` and returns 500 instead of typed unavailable health. | P2 | `RootElement.ValueKind == Object` is checked before reading version in `Infrastructure/Integrations/IntegrationHealth.cs:17`; other JSON roots now follow `invalid_response`. |

The reviewed HTTP path validates every destination, resolves DNS at connection time, rejects mixed unsafe address sets, and connects to the validated literal address. Automatic redirects, proxies and cookies are disabled. Content requests have bounded headers/body/time/concurrency; the private-address exception and administrative API key are restricted to the exact configured service origin. Redirects are revalidated, limited and checked for HTTPS downgrade. No concrete credential forwarding or DNS-rebinding bypass was found in those paths. Private result references are encrypted at rest and omitted from client result views; cursors and snapshots bind the user and permission stamp.

Source resolution also takes one of two singleton admission slots before loading or parsing payloads. Persisted source alternatives are bounded to 32KiB plaintext and 100 entries. Health testing rechecks the current normal access credential and administrator role both before and after upstream I/O, returns only fixed safe details, and holds no writer gate while waiting for HTTP. The query worker consumes returned provider-health metadata, distinguishing an unavailable provider's empty response from a genuine successful empty search and invoking stale fallback when every provider fails.

## Boundary and verification limits

M04 validates source provenance and does not start transfers. M05 must independently recheck destination permission, quotas, metadata mapping and stopped admission immediately before using a resolved source. Application tracker checks do not pin qBittorrent's later DNS lookup or isolate daemon egress; the documented container/host policy and its controlled-fixture tests remain separate required gates. No claim is made here that HTTP checks alone contain the torrent daemon.

This review does not certify ARM64/Pi execution, real private indexers, production deployment or release readiness. Prowlarr and libtorrent compatibility experiments were performed by the parent/workers, not independently repeated by this reviewer. Host administration remains trusted; the assessed boundary is an ordinary user's authorized API access to untrusted discovery metadata.
