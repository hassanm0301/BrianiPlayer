# M04 metainfo and source transport profile

The bounded parser accepts v1, v2 and hybrid metainfo, computes hashes of the exact original encoded `info` substring and validates v2 Merkle layers. Canonical dictionary ordering/integers, paths, symlinks, ambiguous case/NFC duplicates and file/ancestor collisions are checked. V1 piece lengths can be positive integers up to the planned64MiB limit; v2 requires powers of two from16KiB. A stopped no-payload experiment on the actual pinned qBittorrent5.2.4 accepted v1 lengths12345 and67108864 (`piece-profile.log`). Uploaded files are at most16MiB,10000 files,64 nesting levels,100000 bencode nodes; component/path UTF8 sizes are at most255/4096 bytes. Shared Merkle roots are verified once per unique layer.

V2 raw trees are rootless. The parser maps single files without a duplicated name and applies the pinned engine's named-root convention for multifile layouts. Hybrid path/size order and piece alignment must agree. Exact engine file IDs/offsets/padding validation remains the separate M05 admission/M06 layout boundary; this parser does not authorize guessed playback offsets.

Metainfo is preserved intact. Webseeds (`url-list`,`httpseeds`) and explicit `nodes` are rejected in this default profile; unsafe tracker endpoints are rejected. Magnets accept BitTorrent v1 hex/base32 and v2 SHA256 multihashes, a64KiB URI limit and bounded `dn`,`xl`,`tr` fields; unsupported metadata/webseed/peer fields are rejected. Tracker DNS is revalidated before resolution succeeds; daemon egress policy and admission-time checks remain M05/M10 work.

Content fetches use a per-connection pinned DNS result, no proxy/cookies/automatic redirects, ordinary TLS certificate validation,20-second HTTP deadlines,25-second source deadlines, two concurrent resolves, and bounded headers/payloads. Redirects are capped at5, loops and HTTPS downgrades rejected. Only the exact administrator-configured Prowlarr origin can reach approved private service addresses or receive its API key. Other destinations require approved public addresses and HTTP/HTTPS ports80/443. IPv4-mapped IPv6 is classified by its embedded IPv4 address. Reserved/documentation/translation/tunnel ranges are rejected conservatively; this is an application allow policy, not a claim to describe every globally routable prefix.

Connection secrets use the server's restricted AES-GCM store and never appear in normal responses. Raw discovery URLs are encrypted internally. Source re-resolution checks original provider/source identity and expected hashes. Permissions are checked again after asynchronous source lookup, and uploads are checked again for expiry. Uploaded files use opaque UUID paths in private state storage;2 prebinding upload slots, multipart/body caps,4 retained records/user and32 globally, periodic/admission expiry+orphan cleanup prevent accumulated temporary storage. Unknown changed files are preserved for diagnostics rather than guessed safe to delete.

Primary references inspected: [BEP3](https://www.bittorrent.org/beps/bep_0003.html), [BEP52](https://www.bittorrent.org/beps/bep_0052.html), [.NET10 ConnectCallback](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.socketshttphandler.connectcallback?view=net-10.0), [IANA IPv4 special registry](https://www.iana.org/assignments/iana-ipv4-special-registry), and [IANA IPv6 special registry](https://www.iana.org/assignments/iana-ipv6-special-registry). Upstream API behavior is additionally verified with the pinned Prowlarr fixture profile.
