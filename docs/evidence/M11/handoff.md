# Briani Player implementation handoff

The M00–M11 application implementation is present and packaged as a private local candidate. The server uses the required Docker Compose, .NET 10, SQLite, Prowlarr and qBittorrent stack. Native Flutter clients include folder/photo browsing, discovery, download controls, progressive embedded playback, external-player handoff, accounts, library permissions, preferences and TV navigation. No service or app was published.

The final review resolved independent download/manage permission handling, permission changes between engine actions, rejected foreign-manager commands affecting another owner's transfer state, shared-job attachment locking and request-owner quota attribution. Original owner-revocation behavior remains covered. A desktop integration-report race was fixed with atomic report publication; application client code and packaged client binaries were unchanged by that fixture correction.

Local verification passed 412 server tests across ten suites, 134 Python tooling tests plus 21 subtests, and the retained 86 Flutter unit/widget tests. Final Flutter analysis found no issues. The rebuilt server completed the Linux desktop progressive-playback scenarios and Android TV emulator workflow, including rendered video before download completion, buffering/resume, navigation and import. The test variants establish connected playback; optimized package startup has separate evidence.

The final four-service retained-media restore preserved partial file inode/hash, request ownership, grants, idempotency replay, secret key and torrent identity. Recheck checking/completion were observed, the download resumed to 8 MiB, and its SHA-256 matched the generated source. The staged operations package also passed installation, a 603-file configuration backup, restore and rollback. Temporary stacks, fixture media, scratch directories and five exact owned subnet reservations were removed. No Raspberry Pi or physical Android tests were performed.

Seven artifacts are indexed in `dist/manifest.json`: amd64 server/egress images, ARM64 server and egress images, optimized Linux bundle, unsigned optimized Android APK, ordinary debug-signed Android test APK, and operations bundle. Source snapshots, notices, dependency inventories, SBOM and provenance accompany them. Every one of the 843 checksum entries passed; independent review found no final artifact/evidence/source mismatch.

Release certification remains blocked. Pi and physical Android checks are reserved to the owner; Windows/macOS runners and release signing are unavailable. Native binary/source correspondence and license inventory remain qualified, some critical branches remain below the coverage target, and unassisted qBittorrent reconnect reliability is unresolved. The package audit and release verifier correctly exit 3.
