# M10 final local acceptance tests

Date: 2026-10-13  
Scope: focused server component/API acceptance gaps for T13, T15, T16, T18 and T24. Tests use temporary SQLite and generated files; torrent engine and blocked response-body adapters are fakes. They do not replace real-engine, crash-process, device or Pi evidence.

## Added scenarios

- `Briani.DownloadTests.FinalAcceptanceTests.Shared_hash_isolation_keeps_control_and_quota_per_user_and_hides_other_library_conflict` creates two user requests for one managed hash, confirms one physical job, denies the first owner's pause while the request is shared, verifies a same-hash request aimed at another library yields a neutral conflict without exposing the original library or hash, and checks the contributor's live per-user quota before selection.
- `Briani.DownloadTests.FinalAcceptanceTests.Refreshed_session_logout_aborts_an_open_progressive_response_on_watchdog_tick` refreshes a member session while the progressive response is blocked after its first write, logs out with the rotated access token, and verifies the watchdog aborts the response and releases its reader lease.
- `Briani.DownloadTests.FinalAcceptanceTests.Download_layout_preserves_offsets_and_piece_intersections_above_four_gibibytes` maps a file after a 4 GiB-plus prefix and checks the resulting 64-bit offset, piece indexes, available byte count and contiguous prefix behavior.
- `Briani.IdentityTests.FinalAcceptanceTests.Refreshed_access_and_refresh_tokens_are_revoked_when_administrator_disables_account` exercises login, refresh rotation, active access, administrator disable, and denial of the rotated access and refresh credentials.
- `Briani.MediaTests.FinalAcceptanceTests.Revoked_read_grant_denies_photo_video_thumbnail_completed_ticket_and_derived_subtitle` proves a read-granted member can access photo/video metadata, photo bytes and thumbnail, completed media ticket and derived subtitle; after grant revocation every listed resource and the owned playback status returns 404.
- The media test now repeats those decisions over all eight read/download/manage grant combinations, verifies a second user with read access cannot inspect the owner's playback status, and treats stream/subtitle URLs as bearer-bound to the original owner session while checking that owner's current read grant.
- `Briani.DownloadTests.FinalAcceptanceTests.Foreign_download_identifiers_require_read_and_manage_for_every_grant_combination` checks summary, file and list visibility for a foreign owner's request under every grant-bit combination; only read plus manage exposes those identifiers.
- `Briani.DownloadTests.FinalAcceptanceTests.Manage_only_grant_can_control_existing_foreign_request_but_cannot_create_or_work_after_revocation` verifies manage-only settings/pause/resume controls against a registered root-bound fake engine, blocks new source creation, revokes manage after queue while retaining CanDownload, verifies no engine call and no owner-job desired-state poisoning (including a poll tick), and confirms read-only denial. `Manage_only_owner_can_remove_own_request_without_deleting_shared_data` covers owned non-delete removal with the staged payload retained.
- `Briani.DownloadTests.FinalAcceptanceTests.Revoking_manager_during_shared_remove_stops_before_second_priority_write_or_catalog_removal` pauses the worker inside its first priority call, revokes manager access while retaining CanDownload, releases it, then verifies no second priority write, no start, and neither shared request was marked removed.
- `Briani.DownloadTests.FinalAcceptanceTests.Same_hash_attachment_waits_for_existing_job_lock_then_joins_the_owned_job` holds the existing torrent-job lock while an authorized same-hash API create waits, then confirms it attaches to the same job after release.
- `Briani.DownloadTests.FinalAcceptanceTests.Foreign_manager_selection_quota_is_attributed_to_request_owner` is a two-case theory: a manager's tiny quota does not block selection when the request owner has enough quota, while an owner's insufficient quota returns `quota_exceeded` before an operation is queued even when the manager has no quota limit.
- `Briani.IdentityTests.FinalAcceptanceTests.Download_control_checks_every_grant_combination_and_uses_database_role` checks 96 decisions across eight grant combinations, read-only state, owner/shared/destructive controls, and claimed member/administrator roles while the database role remains member.
- `Briani.MediaTests.FinalAcceptanceTests.Oversized_image_header_is_bounded_before_thumbnail_decoder_runs` submits a 20,001 × 20,001 header-only PNG in a tiny generated file. Locked `ffprobe` 9.0.2, with the 40-million-pixel bound, rejects it as `invalid_media`; a marker adapter proves the thumbnail `ffmpeg` process is never launched.

- Existing image authorization covered no-grant denial and generation staleness in `DeliveryApiTests.Image_and_thumbnail_require_current_generation_and_library_access`; this addition specifically exercises revocation after access was granted and extends that transition across completed playback and a derived subtitle URL. ## Limits

The new shared-hash and auth/watchdog tests use the test host and fake torrent adapter. The large-offset case tests metadata-to-engine mapping and piece arithmetic without creating a multi-gigabyte file or running qBittorrent. The media authorization matrix is local API evidence, and the oversized-image test uses real bounded ffprobe plus a marker instead of starting ffmpeg. The header does not contain a full encoded image, so it verifies safe rejection before decode rather than stress-testing a real decompression bomb. Full real-engine and hardware evidence remains in the milestone report and existing artifacts; this handoff makes no new real-engine, Pi, Android hardware, Windows or macOS claim.
